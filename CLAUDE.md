# Working on NeoDesk

NeoDesk is an Android remote-desktop **client** built on RustDesk's prebuilt
engine, with the entire UI and gesture system replaced. Read this before
changing anything under `overlay/`, `patches/`, or `scripts/`.

---

## 1. The one idea that explains the repo

**RustDesk's source is not vendored here.** `rustdesk/` is a *generated,
gitignored build directory*. It is rebuilt from three tracked inputs:

```
upstream RustDesk @ tag        (cloned on demand, never committed)
      + patches/*.patch        small edits to upstream files
      + overlay/**             files we own outright
      ────────────────────────────────────────────────
      = rustdesk/              disposable; safe to delete any time
```

`scripts/sync-rustdesk.ps1` performs that assembly. Everything it needs is
pinned in `rustdesk.lock.json`.

> **Never edit `rustdesk/` directly.** Your change will be silently erased by the
> next sync. Edit `overlay/` or a patch instead, then re-run the sync.

### Which of the two do I put my change in?

| Situation | Where | Why |
|---|---|---|
| The file does not exist upstream (our adapter, `NeodeskBridge.kt`, icons, the bridge, `plugin_overrides/`) | `overlay/` | nothing to merge with |
| The file is binary (PNG, `.jar`, `.so`) | `overlay/` | patches cannot express binary |
| We want upstream's content *plus* a small change (`main.dart`, `common.dart`, `build.gradle`, `AndroidManifest.xml`, `MainActivity.kt`, `gradle.properties`, `pubspec.yaml`) | `patches/` | **a patch fails loudly when upstream moves; an overlay copy silently freezes upstream's version forever** |

That last column is the whole design rationale. Prefer a patch whenever the file
also exists upstream, and keep patches minimal.

### Regenerating a patch after you edit a file

```powershell
# edit rustdesk/<path> to try something out, then capture it:
$up = ".cache\rustdesk-<tag>\flutter\<path>"
git diff --no-index --strip-trailing-cr $up rustdesk\<path> > patches\<name>.patch
# then re-run the sync from scratch and confirm it still applies
```

Patch paths are `a/<path>` / `b/<path>` relative to the flutter dir. Our tree is
CRLF on Windows, so always diff with `--strip-trailing-cr` or every line reads as
changed.

## 2. The two binaries, and why they are special

Everything else here is either ours (in git) or upstream text (re-downloadable
forever). These two are neither:

| File | What it is | Where it comes from |
|---|---|---|
| `overlay/lib/generated_bridge.dart` (+`.freezed.dart`) | The Dart↔Rust FFI declarations — 327 functions, generated by flutter_rust_bridge from RustDesk's Rust source | **Committed.** 480 KB, and not regenerable without a full Rust toolchain (see §5) |
| `librustdesk.so` | The engine itself: protocol, encryption, video codecs. 31 MB of Rust compiled to ARM | **Extracted from the official release APK** by the sync script — a GitHub release asset, so it never expires (CI artifacts do, after ~90 days) |

**They must agree.** The bridge looks up each function by symbol name in the
`.so`:

- bridge declares a symbol the `.so` lacks → crash **when that function is
  called**, not at startup;
- signatures disagree → silent memory corruption, no error at all.

The sync script checks the first direction on every run and fails hard if the
engine exports anything the bridge is missing. It only *warns* the other way,
because a superset is survivable as long as nothing calls the extra symbol.

**Right now there is exactly one such extra:** `wire_session_set_common`. The
bridge is generated for 1.4.9; the engine is still 1.4.7, which does not export
it. `patches/lib_common.patch` removes its only call site (1.4.9's non-E2EE
warning dialog). Look for `NEODESK DEVIATION` in the source for the marker.

This is why `rustdesk.lock.json` has **two** version fields: `rustdesk.tag`
(source) and `engine.tag` (the prebuilt `.so`). They are allowed to differ.

## 3. When upstream releases a new RustDesk

1. **Check the FFI delta first — this is the go/no-go.** The engine pins the
   ABI, so compare the Rust FFI surface between the current and target tags:

   ```bash
   for t in <old> <new>; do
     curl -sL https://raw.githubusercontent.com/rustdesk/rustdesk/$t/src/flutter_ffi.rs \
       | grep -o "^pub fn [a-z_0-9]*" | sort -u > /tmp/fns-$t.txt
   done
   diff /tmp/fns-<old>.txt /tmp/fns-<new>.txt
   ```

   *Added* functions are tolerable — just delete their call sites, as we did for
   `session_set_common`. *Changed or removed* signatures mean the engine must
   move too; do not proceed without also bumping `engine.tag`.

2. **Bump `rustdesk.tag`** in `rustdesk.lock.json` and run
   `.\scripts\sync-rustdesk.ps1`.

3. **Fix whatever fails.** A patch that no longer applies is the system working
   as designed — open the upstream file, see what moved, re-cut the patch
   (§1). Never delete a patch to silence it.

4. **Re-check the deviations table in `DESIGN.md`** — a deviation may have become
   unnecessary (upstream fixed it) or newly wrong.

5. `.\scripts\build.ps1` and confirm the APK builds and the version is right.

### Upgrading the engine as well

Bump `engine.tag` + `apkUrl` + `sha256`, and replace the bridge under
`overlay/lib/` with one generated for the same version. The only reliable way to
get a matching pair is RustDesk's own CI, which publishes both in one run:

```bash
gh run list --repo rustdesk/rustdesk --limit 40 --json databaseId,name
gh api repos/rustdesk/rustdesk/actions/runs/<id>/artifacts \
   -q '.artifacts[] | "\(.name) expired=\(.expired)"'
gh run download <id> --repo rustdesk/rustdesk -n bridge-artifact --dir <out>
```

Those runs build from `master`, not a tag — so always re-verify against the `.so`
(the sync script does this for you).

## 4. Architecture: ports and adapters

```
neodesk_core/            OURS. The redesigned UI + abstract ports. Knows nothing
                         about the engine; runs standalone on FakeCore.
   core/ports/*.dart     the contracts
   core/services/session_manager.dart   NeodeskCore — the aggregate the UI uses
   ui/demo/fake_core.dart               in-memory implementation (+ unit tests)
        ▲ implements
overlay/lib/neodesk/     OURS. The only Dart of ours allowed to touch gFFI/bind.*
        ▲ calls
upstream rustdesk + librustdesk.so
```

**Adding a capability to the UI means adding a port method**, then implementing
it twice: in `FakeCore` (so the demo and tests still compile — the analyzer will
tell you) and in the adapter. Never let UI code import from `rustdesk/`.

Ports live in `neodesk_core/lib/core/ports/`. Keep them engine-agnostic: they
should read as what the *app* needs, not as a wrapper around a `bind.*` call.

## 5. Traps that have actually cost hours

1. **`AppColors` members are static *getters*, not consts.** So
   `const Icon(color: AppColors.x)` fails analyze with "Invalid constant value".
   Drop the `const`. This is the single most common analyze error when editing UI.
2. **`GestureMap` / `GestureTuning` persist the whole table on any single edit**,
   layered over `defaults()`. Changing a default therefore never reaches anyone
   who has opened that settings page — bump `_schema` and extend `_v1Defaults`.
3. **Flutter must be 3.24.5.** Newer Flutter does not compile this RustDesk
   vintage.
4. **Tests and analyze must run with the proxy OFF; builds and `gh` need it ON.**
5. **The bridge cannot be regenerated casually.** It needs Rust 1.75 +
   `cargo-expand` 1.0.95 + `flutter_rust_bridge_codegen` 1.80.1, and
   `cargo metadata` must resolve RustDesk's whole dependency graph including
   large git repos. On a throttled connection this fails. Prefer the CI artifact.
6. **`git apply` inside `rustdesk/`** resolves paths against the *outer* NeoDesk
   repo unless detached from it — the sync script passes `--git-dir=NUL
   --work-tree=. --unsafe-paths` for exactly this reason.

## 6. Account sign-in — third-party only

RustDesk's public server **has username/password login switched off**. It answers
every attempt with *"Username/password login is not available on this server."*
and serves no web console, so there is nothing to register either: the account
*is* the Google / GitHub / Microsoft identity, created on first sign-in.

So `AccountPort` offers only the provider flow. It is a **device-code style**
flow — the engine opens the browser and polls the API server; nothing returns
through a deep link, so no custom URL scheme or manifest entry is needed.

Two asymmetries worth knowing, both already handled in the adapter:

- OIDC: the **Rust side stores the access token** itself.
- Username/password (self-hosted servers only, not implemented): the **Dart side
  must store it** — `UserModel.login()` saves `user_info` but not the token.

## 7. Conventions

- **Do not commit, push, or publish unless asked in that message.**
- Commit messages: English, short, no co-author or email trailers.
- Version lives in `neodesk_core/lib/core/version.dart` (single source of truth);
  the sync script stamps it into `pubspec.yaml`. Bump `neodesk.buildNumber` in
  `rustdesk.lock.json` monotonically or Android refuses the install.
- Scripts are PowerShell (`.ps1`).
- `DESIGN.md` is local-only (gitignored) and holds machine-specific setup, the
  deviation table, and deeper design notes. This file holds the process.
